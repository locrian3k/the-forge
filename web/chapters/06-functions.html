Chapter 6: Functions

Primer: Functions

Making Objects Do Things

Variables store data. Functions act on it. Every function declares a return type, a name, and zero or more typed parameters: 

string query_name()          // takes nothing, returns text
void set_level(int lvl)      // takes a number, returns nothing
int do_add(int a, int b)     // takes two numbers, returns one

Void functions return nothing but must still end with return; per 3K codestyle.

Cross-Object Communication

The -> operator calls a function on another object. This is how the entire MUD works, objects talking to other objects: 

player->query_name()      // ask the player their name
monster->add_hp(-10)      // damage the monster
TP->query_level()         // check command-giver's level

If you remember only one thing about LPC: find the right object, call the right function on it.

Read the Functions chapter of the primer before starting.

Exercise 6.1: Function Basics Apprentice

Practice writing functions with different return types and calling one function from within another.

Requirements

  • Implement void do_greet(): uses write() to display a greeting message. Must end with return;
  • Implement int do_add(int a, int b): returns the sum of a and b
  • Implement string query_title(): returns a title string of your choice
  • Implement string do_combo(int a, int b): calls do_add(a, b) and query_title(), then returns a combined string like "Apprentice of the Forge reports: 3 + 5 = 8"

File to create: exercises/ch06_functions/ex01_function_basics.c

Hints (click to reveal)
  1. Every function must declare its return type before the name. void means it returns nothing, but still needs return; at the end.
  2. Use write("text\n") inside do_greet() to output to the player.
  3. To convert an int to a string for concatenation, use "" + num.
  4. do_combo demonstrates composition, calling your own functions from within another function.

Exercise 6.2: Cross-Object Calls Journeyman

Write two separate objects that communicate with each other using cross-object function calls.

Object 1: scoreboard.c

  • Declare a global mapping kills initialized as ([])
  • Implement void add_kill(string name): increment count for name, or set to 1 if new
  • Implement int query_kills(string name): return the kill count, or 0 if not found

Object 2: reporter.c

  • In create(), get a reference to the scoreboard using find_object()/load_object()
  • Call scoreboard->add_kill("test") to register a kill
  • Call scoreboard->query_kills("test") and store the result
  • Implement int query_result() to return the stored result

Files to create: exercises/ch06_functions/ex02_scoreboard.c and exercises/ch06_functions/ex02_reporter.c

Hints (click to reveal)
  1. find_object(path) returns the object at path if loaded, or 0 if not. load_object(path) forces it to load. Common pattern: ob = find_object(path) || load_object(path);
  2. The -> operator calls a function on another object: other_object->function_name(args).
  3. Make sure the path in the reporter matches where the scoreboard file actually lives.
  4. Store the result in a global variable so query_result() can return it later.

Exercise 6.3: Recursive Power Journeyman

Implement classic recursive algorithms in LPC.

Requirements

  • Declare function prototypes before create() for both functions
  • Implement int factorial(int n):
    • Base case: if n <= 1, return 1
    • Recursive case: return n * factorial(n - 1)
  • Implement int fibonacci(int n):
    • Base case: if n <= 0, return 0
    • Base case: if n == 1, return 1
    • Recursive case: return fibonacci(n - 1) + fibonacci(n - 2)

File to create: exercises/ch06_functions/ex03_recursion.c

Hints (click to reveal)
  1. Function prototypes look like the signature followed by a semicolon: int factorial(int n);, placed before create().
  2. Recursion needs a base case to stop. Without it, you get infinite recursion and the driver kills your object.
  3. factorial(5) should return 120. fibonacci(6) should return 8.
  4. LPC integers are 32-bit, so factorial(12) = 479001600 works but factorial(13) overflows.

Capstone Connection: Phase 1 — The Foundation

Cross-object calls are the lifeblood of MUD programming. Your dungeon rooms will call functions on monsters, monsters will call functions on players, and your area header will coordinate everything. Mastering function calls now pays off in every later chapter.
