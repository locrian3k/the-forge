Timing, Commands, and Functional Programming

These advanced topics let you build dynamic environments that go beyond static descriptions and simple combat.

SystemWhat it doesUse case
set_heart_beat(1)Periodic timer (~2 sec)Ambient messages, ongoing effects
call_out("func", N)One-time delayed callTraps, countdowns, spawns
add_action() in init()Custom player commandsForging, crafting, puzzles
Closures (: :) / #'efunFunctions as valuesfilter(), map(), sort_array()

Heartbeats run every ~2 seconds and cost CPU, always disable them when no players are present. call_out() fires once and is self-cleaning. Closures enable compact functional patterns like filter(arr, (: $1 > 10 :)).

Exercise 19.1: Heartbeat Timer Apprentice

Create a room that uses set_heart_beat() to produce periodic ambient messages.

Requirements

  • Inherit from /room/room
  • Declare a global int beat_counter to track heartbeats
  • In create(): set up the room, initialize beat_counter to 0, and call set_heart_beat(1)
  • Define a heart_beat() function that:
    • Increments beat_counter by 1
    • Every 5 beats (~10 seconds), uses tell_room(TO, msg) to display a random ambient message
    • Has at least 3 different ambient messages
    • Checks if the room is empty using sizeof(filter(all_inventory(TO), #'living)), if no living objects are present, calls set_heart_beat(0) to stop and save CPU
  • Define an init() that calls ::init() and restarts the heartbeat with set_heart_beat(1)

File to create: exercises/ch19_advanced/ex01_heartbeat.c

Hints (click to reveal)
  1. set_heart_beat(1) tells the driver to call your heart_beat() function approximately every 2 seconds. set_heart_beat(0) turns it off. Always turn it off when not needed.
  2. Use the modulo operator: if (beat_counter % 5 == 0), this fires every 5 heartbeats (~10 seconds).
  3. tell_room(TO, message) sends a message to everyone in the room. Pick a random message with messages[random(sizeof(messages))].
  4. The init() function is called whenever a living object enters the room. Restarting the heartbeat there ensures ambient messages resume when a player arrives.

Exercise 19.2: Call Out Trap Journeyman

Create a trap room that uses call_out() to trigger a delayed event when a player enters.

Requirements

  • Inherit from /room/room
  • Set up a trapped room with at least 1 add_item() for the trap mechanism and at least 2 exits
  • Define an init() that:
    • Calls ::init()
    • Checks if (!living(TP)) return; to skip non-living objects
    • Checks if (find_call_out("trigger_trap") != -1) return; to prevent duplicate call_outs
    • Starts a delayed trap with call_out("trigger_trap", 3)
  • Define a trigger_trap() that uses tell_room(TO, message) to describe the trap going off
  • Cancel the trap when the player leaves using remove_call_out("trigger_trap")

File to create: exercises/ch19_advanced/ex02_call_out.c

Hints (click to reveal)
  1. call_out("func_name", seconds) schedules a function to be called after the given number of seconds. Unlike heart_beat, a call_out fires once and is then gone.
  2. find_call_out("func_name") returns the remaining seconds until the call_out fires, or -1 if none exists. Always check before scheduling to prevent duplicates.
  3. remove_call_out("func_name") cancels a pending call_out. Use this when the player leaves so the trap does not fire on an empty room.
  4. In trigger_trap(), the original this_player() from init() may no longer be valid. Either store the player reference, or iterate over all_inventory(TO) to find living objects still in the room.

Exercise 19.3: Command Hook Journeyman

Create a room with a custom player command that checks inventory, consumes an item, and produces a result object.

Requirements

  • Inherit from /room/room
  • Set up a forge/workshop room with at least 2 add_item() calls and at least 1 exit
  • Add a custom command in init(): add_action("do_forge", "forge")
  • Implement do_forge(string arg) that returns int:
    • If arg is missing or not "sword", sets notify_fail() and returns 0
    • Checks if the player has an "iron bar" using present("iron bar", TP)
    • If no iron bar: sets notify_fail() and returns 0
    • If found: destructs the iron bar, clones a result weapon, moves it to the player
    • Writes success messages with write() and tell_room(TO, msg, ({TP}))
    • Returns 1

File to create: exercises/ch19_advanced/ex03_command_hook.c

Hints (click to reveal)
  1. add_action("function_name", "command") in init() registers a command. When a player types forge sword, do_forge("sword") is called.
  2. present("name", TP) searches the player's inventory for a matching object. It returns the object if found, or 0 if not.
  3. notify_fail("message\n") sets the failure message shown when your function returns 0. Always include \n at the end.
  4. When you destruct() the iron bar, it is gone forever, this is how crafting consumes materials. clone_object() creates a fresh copy of the result item.

Exercise 19.4: Closures Journeyman

Write an object that demonstrates three closure styles used in LPC.

Requirements

  • Declare three global arrays: int *numbers, string *names, int *high_values
  • In create(): initialize numbers with at least 6 unsorted integers, names with at least 4 name strings, then call three processing functions
  • Define sort_numbers():
    • Uses sort_array() with an efun closure #'< to sort ascending
    • Example: numbers = sort_array(numbers, #'<);
  • Define filter_high():
    • Uses filter() with an inline closure to keep only values above 20
    • Example: high_values = filter(numbers, (: $1 > 20 :));
  • Define title_names():
    • Uses map() with an inline closure to append " the Brave" to each name
    • Example: names = map(names, (: $1 + " the Brave" :));
  • Define query functions: query_numbers(), query_high_values(), query_names()

File to create: exercises/ch19_advanced/ex04_closures.c

Hints (click to reveal)
  1. #'< is an efun closure, a reference to the built-in less-than operator. sort_array(arr, #'<) sorts in ascending order. #'> would sort descending.
  2. Inline closures use the (: code :) syntax. Inside them, $1 is the first argument, $2 the second. filter(arr, (: $1 > 20 :)) keeps elements where the closure returns true.
  3. map(arr, closure) returns a new array where each element is the result of calling the closure on the original. map(names, (: $1 + " the Brave" :)) appends the title to every name.
  4. These three closure styles cover most functional operations in LPC: sorting with efun references, filtering with inline predicates, and transforming with inline mappers.

Capstone Connection — Phase 4: The Boss & Phase 5: Polish

These advanced techniques are the finishing touches that elevate a good dungeon into a great one. Heartbeats create atmospheric rooms that feel alive. Call_outs power traps, puzzles, and timed events. Custom commands let players interact with your dungeon in unique ways. And closures give you the tools to write clean, efficient code for complex game logic. Use them all in your capstone area.
