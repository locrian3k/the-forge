Chapter 17: Monsters

Read the primer: Monsters

Three Tiers of Enemies

Monsters are the creatures players fight. 3Kingdoms provides three base classes, each more powerful than the last:

Base ClassUse ForKey Features
/obj/monsterSimple foesName, level, chat messages
/obj/complex_monsterSpell casters+ spell attacks with multiple damage types
/obj/super_monsterBosses+ damage reduction, death events, loot

All monsters share core properties: name, race, level, alignment, and descriptions. They can have idle chat (ambient dialogue), combat chat (battle taunts), and extra_look() for conditional flavor text.

These exercises progress from a simple aggressive monster through a spell caster to a full boss encounter.

Read the Monsters chapter of the primer before starting.

Exercise 17.1: Basic Monster Apprentice

Create a simple monster that could inhabit a dungeon room.

Requirements

  • Inherit from /obj/monster
  • Define a create() function that:
    • Calls ::create() as its first action
    • Sets the monster's name to "cave goblin" using set_name()
    • Sets aliases with set_alias() including at least "goblin" and "cave goblin"
    • Sets the race to "goblin" using set_race()
    • Sets short and long descriptions (long description at least two sentences)
    • Sets the level to 5 using set_level()
    • Sets alignment to -200 using set_al() (negative = evil)
    • Sets the monster as aggressive with set_aggressive(1)
    • Loads at least 3 idle chat messages using load_chat(percentage, array)
  • Define an extra_look() function that returns a string describing what the goblin is currently doing
  • Use 2-space indentation, Allman bracket style

File to create: exercises/ch17_monsters/ex01_basic_monster.c

Hints (click to reveal)
  1. The inherit "obj/monster"; line goes after your #include but before any functions. This gives your object all the standard monster behaviors.
  2. load_chat() takes a percentage (integer) and an array of strings. Each string must end with \n. Example: load_chat(10, ({"The goblin scratches itself.\n", "The goblin growls.\n"}));
  3. extra_look() takes no arguments and returns a string. This is what players see appended after the monster's short description in a room.
  4. set_aggressive(1) means the monster attacks players on sight. Alignment ranges from -1000 (very evil) to 1000 (very good).

Exercise 17.2: Chat and Spells Journeyman

Create a complex monster with a spell system that uses multiple damage types and combat chat messages.

Requirements

  • Inherit from /obj/complex_monster
  • Set name, alias, race, short, and long descriptions for a dark mage
  • Set level to 12, negative alignment, and set_aggressive(1)
  • Configure at least 3 spell attacks using the spell array system:
    • set_spell_mess1(), array of attack messages seen by the room (use $N$ for the target's name)
    • set_spell_mess2(), array of attack messages seen by the target
    • set_spell_type(), array of damage types (e.g., "fire", "ice", "acid")
    • set_spell_dam(), array of base damage values (negative numbers for scaling damage)
    • set_spell_probabilities(), array of integer weights for spell selection
  • All spell arrays must be the same length
  • Load combat chat messages using load_a_chat(percentage, array)
  • Load idle chat with load_chat()
  • Define extra_look() returning an intimidating description

File to create: exercises/ch17_monsters/ex02_chat_spells.c

Hints (click to reveal)
  1. The spell arrays work in parallel, index 0 of each array describes the first spell, index 1 the second, and so on. If you have 3 spells, each array must have exactly 3 elements.
  2. set_spell_dam() uses negative values to indicate scaling damage. A value of -80 means "80% of monster level as base damage."
  3. set_spell_probabilities() are relative weights, not percentages. ({3, 1, 1}) means the first spell is chosen 3 times as often as either of the others.
  4. load_a_chat() works exactly like load_chat() but only triggers during active combat.

Exercise 17.3: Boss Monster Journeyman

Create a boss-tier monster using /obj/super_monster with damage reduction, a death narrative, custom death messages, and a loot drop.

Requirements

  • Inherit from /obj/super_monster
  • Set name, alias, race, short, and long descriptions for a boss monster
  • Set level to 20, strongly negative alignment, and set_aggressive(1)
  • Add add_property("NOPEACE") so players cannot use the peace command
  • Set set_dead_ob(TO) so the monster handles its own death events
  • Call add_clone(path) with a path to a weapon or armor that the boss drops on death
  • Set up at least 2 spell attacks using the spell array system
  • Load combat and idle chat messages
  • Define modify_damage(int dam, string dam_type, int *att_wc), returns a reduced damage value (e.g. dam / 2 for 50% reduction)
  • Define monster_died(), uses tell_room() to narrate the death, then moves all inventory to the room
  • Define query_death_message(object for_who), returns the message shown to a player killed by this boss
  • Define extra_look() returning a boss-tier description

File to create: exercises/ch17_monsters/ex03_boss.c

Hints (click to reveal)
  1. modify_damage() is called every time the boss takes a hit. Return the modified damage value. Returning dam / 2 halves all incoming damage.
  2. set_dead_ob(TO) tells the driver to call monster_died() on this object when the monster dies. Without it, monster_died() is never called.
  3. add_clone(path) adds an object to the monster's inventory that becomes the boss's loot drop when monster_died() moves inventory to the room.
  4. In monster_died(), use environment(TO) to get the room. Move inventory with: map(all_inventory(TO), #'move_object, environment(TO));

Capstone Connection — Phase 3: Combat

Monsters bring your dungeon to life. Use basic monsters for common encounters, complex monsters for challenging mid-dungeon fights, and a super_monster for your capstone boss. The boss fight is the climax of your area, give it damage reduction, dramatic death narration, and a unique loot drop that players will remember.
