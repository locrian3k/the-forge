Chapter 5: Mappings & Arrays

Primer: Mappings & Arrays

Lists and Dictionaries

Once you can store single values, you need containers for collections. LPC gives you two:

Arrays are ordered lists: ({ "sword", "axe", "dagger" }). They are zero-indexed, weapons[0] is "sword", weapons[1] is "axe". Use arrays when order matters or you need a simple list.

Mappings are key→value dictionaries: ([ "Steve" : 5, "Bob" : 2 ]). Look up a value by its key: kills["Steve"] returns 5. Use mappings when you need to associate names with data, inventories, stat blocks, scoreboards.

Mappings can be nested, a mapping whose values are themselves mappings. This is how complex game data like monster stat blocks and bestiaries are typically stored.

Read the Mappings & Arrays chapter of the primer before starting.

Exercise 5.1: Inventory Tracker Apprentice

Create an object that uses a mapping to track item names and their quantities.

Requirements

  • Declare a global mapping variable inventory initialized as ([]) in create()
  • Implement void add_item(string name, int qty):
    • If name already exists, add qty to the existing value
    • If name does not exist, create a new entry with the given qty
  • Implement void remove_item(string name):
    • Delete the entry for name using map_delete()
  • Implement int query_item(string name):
    • Return the quantity for name, or 0 if not found
  • Implement string *list_items():
    • Return a sorted array of all item names using keys() and sort_array()

File to create: exercises/ch05_mappings/ex01_inventory_tracker.c

Hints (click to reveal)
  1. An empty mapping is created with ([]). Assign values with mapping[key] = value.
  2. To check if a key exists, test if (mapping[key]), but be careful, a quantity of 0 is falsy. For this exercise, quantities are always positive when added.
  3. map_delete(mapping, key) removes a key-value pair. keys(mapping) returns a string array of all keys.
  4. sort_array(array, 1) sorts ascending; -1 would mean descending.

Exercise 5.2: Monster Bestiary Journeyman

Build a nested mapping structure, a bestiary of monsters where each entry maps a monster name to an inner mapping of its stats.

Requirements

  • Declare a global mapping bestiary and populate it in create() with at least 5 monsters
  • Each entry maps a monster name (string) to an inner mapping with keys:
    • "level" : int
    • "race" : string (e.g., "undead", "goblin", "dragon")
    • "aggressive" : status (1 or 0)
  • Implement mapping lookup(string name):
    • Return the inner mapping for the given monster, or 0 if not found
  • Implement string strongest():
    • Iterate over all monsters and return the name of the one with the highest level
    • Return "none" if the bestiary is empty
  • Implement string *aggressive_list():
    • Return a sorted array of names where "aggressive" is 1
    • Return ({}) if none exist

File to create: exercises/ch05_mappings/ex02_bestiary.c

Hints (click to reveal)
  1. Nested mappings look like: (["goblin": (["level": 3, "race": "goblin", "aggressive": 1])])
  2. Access nested values with: bestiary["goblin"]["level"]
  3. Use foreach (string name, mapping stats in bestiary) to iterate over all entries.
  4. Build up a result array with += (e.g., result += ({ name })) when filtering, then sort_array() it.

Capstone Connection: Phase 1 — The Foundation

Mappings are everywhere in MUD code: room exits, monster stat blocks, item properties, loot tables. Your capstone dungeon will use mappings to configure rooms, define monster data, and track player progress through the area.
