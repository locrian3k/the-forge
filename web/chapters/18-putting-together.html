Chapter 18: Putting It Together

Read the primer: Putting It Together

From Files to an Area

Building a complete area means organizing rooms, monsters, and objects into a coherent structure. The architecture follows a consistent pattern: 

your_area/
├─ defs.h          → path constants shared by all files
├─ rooms/
│   ├─ base_room.c → base room all area rooms inherit
│   ├─ entrance.c  → entry point (inherits /room/room)
│   ├─ rm2.c       → area room (inherits base_room.c)
│   ├─ rm3.c
│   └─ rm4.c
├─ mon/
│   └─ goblin.c    → monsters
└─ obj/
    └─ key.c       → items and treasures

The defs.h header defines paths so every file can reference TRAINING_ROOM + "rm2" instead of hardcoding full paths. The base_room.c base room handles shared setup so individual rooms stay short. The driver's reset() cycle keeps rooms populated by respawning monsters after they are killed.

These exercises walk you through the full area architecture, from the header file to a working multi-room area with monster spawning.

For dungeon-specific area building with level scaling, see Chapters 20-21.

Read the Putting It Together chapter of the primer before starting.

Exercise 18.1: Area Header Apprentice

Create a defs.h header file for a new area.

Requirements

  • #pragma strong_types must be the first line of the file
  • Include the parent header with #include "../defs.h"
  • Define the following path constants using #define:
    • TRAINING, the area root path: AREAS + "training/"
    • TRAINING_ROOM, path to rooms: TRAINING + "rooms/"
    • TRAINING_MOBS, path to monsters: TRAINING + "mon/"
    • TRAINING_ITEM, path to objects: TRAINING + "obj/"
  • Use UPPERCASE naming for all #define macros
  • Comment each define to explain its purpose

File to create: exercises/ch18_putting_together/defs.h

Hints (click to reveal)
  1. The AREAS macro is defined in the global defs.h and points to the base areas directory. Your area paths build on top of it.
  2. Each #define creates a text substitution. When you write TRAINING_ROOM + "rm2" later in your code, the preprocessor expands it to the full file path string.
  3. All area defs.h files follow this exact pattern. Look at any existing area for reference.

Exercise 18.2: Area Layout Journeyman

Create an entrance room and three connected rooms to form a small area layout.

Requirements

Create four files:

  • ex02_entrance.c, The outdoor entrance:
    • Inherit from /room/room
    • Set light, short, and long descriptions
    • Add at least 2 add_item() calls
    • Add an exit north to TRAINING_ROOM + "ex02_rm2"
  • ex02_rm2.c, First interior room:
    • Inherit from /room/room
    • Exits: south to ex02_entrance, east to ex02_rm3
  • ex02_rm3.c, Second interior room:
    • Inherit from /room/room
    • Exits: west to ex02_rm2, north to ex02_rm4
  • ex02_rm4.c, Third interior room (dead end):
    • Inherit from /room/room
    • Exit: south to ex02_rm3

All rooms must have bidirectional exits, use TRAINING_ROOM defines for paths, and follow 3K codestyle.

Files to create: exercises/ch18_putting_together/ex02_entrance.c
exercises/ch18_putting_together/ex02_rm2.c
exercises/ch18_putting_together/ex02_rm3.c
exercises/ch18_putting_together/ex02_rm4.c

Hints (click to reveal)
  1. All rooms inherit /room/room, which provides the standard room functionality including exits, items, and searching.
  2. add_exit(path, direction) creates a one-way exit. You must add the reverse exit in the destination room to make movement bidirectional.
  3. The entrance room uses TRAINING + "ex02_entrance" as its path (not TRAINING_ROOM) because it lives in the area root directory.
  4. Each room should have its own theme and description. Even simple rooms benefit from at least one add_item() call for atmosphere.

Exercise 18.3: Base Area Room Journeyman

Create an inheritable base room (base_room.c) that all rooms in your area inherit from.

Requirements

  • Include the header with #include "../defs.h" (base_room.c lives in rooms/ subdirectory)
  • Inherit from /room/room
  • Define a create() that calls ::create() and sets light
  • Define a block_them(string arg) function that:
    • Uses query_verb() to get the direction the player typed
    • Checks if the direction exists in query_exits() or query_hidden()
    • Blocks movement (returns 1) if the direction is not a valid exit
    • Allows movement (returns 0) if the direction is a valid exit
  • Define an init() that calls ::init() and registers block_them with add_action("block_them", "", 1)

File to create: exercises/ch18_putting_together/ex03_droom.c

Hints (click to reveal)
  1. The ex03_droom.c file acts as a middle layer: it inherits /room/room and your actual rooms inherit ex03_droom.c. This lets you put common setup in one place.
  2. block_them() prevents players from walking into walls. The add_action("block_them", "", 1) trick catches ALL player commands.
  3. query_exits() returns a mapping of visible exits. query_hidden() returns hidden exits. Use member(mapping, key) to check if a direction exists.
  4. Keeping the base room simple means child rooms only need to add their own descriptions, items, and exits. Shared logic lives here.

Exercise 18.4: Reset Spawning Journeyman

Create a room that uses reset() and clone_object() to respawn monsters.

Requirements

  • Inherit from the ex03_droom.c base room created in Exercise 18.3
  • Define a create() that:
    • Calls ::create()
    • Sets short and long descriptions
    • Adds at least 1 add_item() for scenery
    • Adds at least 1 exit
  • Define a reset() that:
    • Calls ::reset()
    • Uses present("monster_id") to check if the monster already exists in the room
    • If the monster is not present, uses clone_object(TRAINING_MOBS + "goblin") to create one and move_object() to place it in the room
    • This present() check + clone_object() approach prevents duplicate monsters from stacking up

File to create: exercises/ch18_putting_together/ex04_spawn_room.c

Hints (click to reveal)
  1. reset() is called by the driver periodically (roughly every 30-45 minutes) to repopulate rooms. It is also called once after create() when the room first loads.
  2. Always call ::reset() at the start of your reset() function. The parent's reset handles internal bookkeeping.
  3. The pattern is: if (!present("goblin")) { object ob = clone_object(TRAINING_MOBS + "goblin"); move_object(ob, TO); }. The present() check prevents duplicates.
  4. clone_object(path) creates a new copy of an object. move_object(ob, TO) places it in the current room. Together with present(), this is the standard respawn pattern for /room/room areas.

Capstone Connection — Phase 4: The Boss

This is where your capstone area truly comes together. The header file, area layout, base room, and reset spawning are the architectural backbone of every 3Kingdoms area. With these pieces in place, you have a fully functional area skeleton ready to be populated with the monsters, weapons, armor, and objects you built in earlier chapters.
