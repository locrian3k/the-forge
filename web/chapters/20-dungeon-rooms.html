Chapter 20: Dungeon Rooms

Read the primer: Rooms

3K Extension. This chapter covers the dungeon room system specific to 3Kingdoms. Skip it if your MUD does not have /room/dungeon/dr.c.

Standard Rooms vs Dungeon Rooms

In Chapter 13 you built rooms using /room/room. The dungeon room layer, /room/dungeon/dr.c, extends that base with automatic level scaling. Monsters spawned inside a dungeon room have their stats adjusted to match the dungeon's configured level, so one monster file can serve areas of different difficulty.

The key function is set_dungeon(name, level, scale_hp, scale_damage, scale_exp):

ParameterTypePurpose
namestringDungeon display name, shown in the area header
levelintBase difficulty level for monster scaling
scale_hpint1 to scale monster hit points, 0 to leave raw
scale_damageint1 to scale monster damage, 0 to leave raw
scale_expint1 to scale monster experience, 0 to leave raw

Dungeon rooms also provide the add_clone() helper, which clones an object into the room and handles respawn bookkeeping automatically. This is more convenient than the manual present() + clone_object() pattern used in standard rooms.

When to use dungeon rooms: Use /room/dungeon/dr.c when you want automatic level scaling for monsters and the convenience of add_clone(). Use /room/room for entrance rooms, outdoor areas, or any room that does not need scaling.

Exercise 20.1: Your First Dungeon Room Apprentice

Create a basic dungeon room using /room/dungeon/dr.c with level scaling.

Requirements

  • Inherit from /room/dungeon/dr.c
  • Call ::create() at the start of your create() function
  • Call set_dungeon("Training Dungeon", 5, 1, 1, 1) to enable level 5 scaling with all three flags on
  • Set room lighting with set_light(1)
  • Set a short description with set_short()
  • Set a long description with set_long() (at least two sentences)
  • Add one exit using add_exit(path, direction)
  • Add at least 1 add_item() call for scenery

File to create: exercises/ch20_dungeon_rooms/ex01_dungeon_room.c

Hints (click to reveal)
  1. Dungeon rooms use inherit "room/dungeon/dr.c"; instead of /room/room. All the standard room functions (exits, items, searching) are still available.
  2. set_dungeon() must be called in create() after ::create(). The first argument is the dungeon name displayed in the area header. The second is the base level that controls monster scaling.
  3. The three scaling flags (hp, damage, exp) are usually all set to 1. Setting one to 0 means that stat will not be adjusted by the dungeon level.
  4. Other than set_dungeon(), everything else works exactly the same as a standard room from Chapter 13.

Exercise 20.2: Spawning with add_clone() Journeyman

Create a dungeon room that uses add_clone() to spawn objects or monsters.

Requirements

  • Inherit from /room/dungeon/dr.c
  • Call set_dungeon() with a dungeon name and level of your choice
  • Set up standard room properties (light, short, long, at least 1 exit, at least 1 item)
  • Use add_clone(path) in create() to spawn at least one monster into the room
  • Define a reset() that:
    • Calls ::reset()
    • Uses add_clone() to respawn the monster
  • Create a simple monster file (inherit /obj/monster) for the spawned creature

File to create: exercises/ch20_dungeon_rooms/ex02_dungeon_features.c

Hints (click to reveal)
  1. add_clone(path) is a dungeon room function that clones an object and moves it into the room. It handles duplicate checking internally, so if the monster already exists, it will not create another.
  2. The path argument should be the full MUD file path without the .c extension. On 3K, wizard files live under /players/yourname/, so the path would look like add_clone(MY_PATH + "mon/cave_rat") using a define from your defs.h. For this exercise, use any placeholder path that shows you understand the pattern.
  3. reset() is called periodically by the driver (roughly every 30-45 minutes). Calling add_clone() in reset() ensures monsters respawn after being killed.
  4. Always call ::reset() first. The parent class uses it for internal dungeon bookkeeping.

Exercise 20.3: Standard vs Dungeon Room Journeyman

Build the same room twice, once with /room/room and once with /room/dungeon/dr.c, to see what the dungeon layer adds.

Requirements

Create two room files with the same theme and layout:

  • ex03_standard.c, Standard version:
    • Inherit from /room/room
    • Set light, short, and long descriptions
    • Add at least 2 add_item() calls and 1 exit
    • In reset(), use the present() + clone_object() + move_object() pattern to spawn a monster
  • ex03_dungeon.c, Dungeon version:
    • Inherit from /room/dungeon/dr.c
    • Call set_dungeon() with a name and level
    • Use the same descriptions, items, and exit as the standard version
    • In reset(), use add_clone() to spawn the same monster

Both rooms should spawn the same monster file. The dungeon version automatically scales the monster's HP, damage, and experience based on the level you set in set_dungeon(), while the standard version uses the monster's raw stats unchanged. Compare the two files to see how little extra code the dungeon layer requires.

Files to create: exercises/ch20_dungeon_rooms/ex03_standard.c
exercises/ch20_dungeon_rooms/ex03_dungeon.c

Hints (click to reveal)
  1. The standard room uses the manual spawn pattern: if (!present("monster_id")) { object ob = clone_object(path); move_object(ob, TO); }. The dungeon room uses: add_clone(path);.
  2. In the dungeon version, the room's set_dungeon() level automatically adjusts the monster's HP, damage, and experience. A level-10 dungeon room makes the same monster significantly tougher than a level-3 room, even though the monster file is identical.
  3. Keep the descriptions identical between the two rooms so the only difference is the inherit and spawning mechanism. This makes the comparison clear.
  4. The monster file itself does not need to know whether it lives in a standard or dungeon room. The dungeon scaling is applied automatically by the room.
