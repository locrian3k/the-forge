Chapter 3: Variables

Primer: Variables

Two Kinds of Memory

Variables in LPC come in two flavors, and understanding the difference prevents one of the most common bugs in MUD coding.

Global variables are declared outside all functions. They persist for the lifetime of the object, set a goblin's hp in create(), and it's still there when attack() runs later.

Local variables are declared inside a function. They are created fresh each time the function runs and destroyed when it returns. They exist only within that function's braces.

The Shadowing Trap

If you declare a local variable with the same name as a global, the local shadows (hides) the global within that function. Changes go to the local copy, and when the function returns, those changes vanish. This is the single most common variable bug in LPC, Exercise 3.2 makes you find and fix one.

Read the Variables chapter of the primer before starting.

Exercise 3.1: Scope Matters Apprentice

Create an object that demonstrates the difference between global and local variable scope.

Requirements

  • Follow all standard 3K codestyle rules
  • Inherit from /obj/treasure
  • Set the name to "scope stone" and short to "a scope stone"
  • Declare a global int variable named counter, initialized to 0 in create()
  • Write a function int do_increment() that:
    1. Declares a local int variable named local_val and sets it to 100
    2. Increments the global counter by 1
    3. Returns local_val
  • Write int query_counter() that returns the global counter

Expected Behavior

Every call to do_increment() returns 100 (the local is always freshly initialized) but increases counter by 1 (the global accumulates). After 3 calls: query_counter() returns 3.

File to create: exercises/ch03_variables/ex01_scope.c

Hints (click to reveal)
  1. Global variables are declared outside all functions, near the top of the file. They keep their value between calls.
  2. Local variables are declared inside a function. They are created when the function runs and destroyed when it returns.
  3. counter++ is shorthand for counter = counter + 1.
  4. The key insight: local_val gets set to 100 every single time do_increment is called, because locals do not persist.

Exercise 3.2: Shadow Bug Fix Journeyman

A fellow coder wrote an object with a counter, but query_counter() always returns 0 no matter how many times do_increment() is called. Find the variable shadowing bug and fix it.

The Buggy File

#pragma strong_types
#include "defs.h"

inherit "obj/treasure";

int counter;

void create()
{
  ::create();

  set_name("shadow counter");
  set_alias(({"counter", "shadow counter"}));
  set_short("a shadow counter");
  set_long("A counting device plagued by shadows.");
  set_value(1);
  set_weight(1);

  counter = 0;

  return;
}

void do_increment()
{
  // BUG: this local declaration shadows the global!
  int counter;

  counter++;

  return;
}

int query_counter() { return counter; }

Requirements

  • Identify the shadowing bug: a local variable in do_increment() has the same name as the global, so counter++ only modifies the local copy
  • Fix the code so that do_increment() modifies the global counter
  • Do not change the function signatures or the query function
  • Maintain all 3K codestyle rules

File to create: exercises/ch03_variables/ex02_shadow_bug.c

Hints (click to reveal)
  1. Look carefully at the first line inside do_increment(). What does int counter; do?
  2. When a local variable has the same name as a global, the local "shadows" the global. All references to that name inside the function affect only the local.
  3. The fix is simple: remove the local declaration so that counter refers to the global.
  4. After fixing, calling do_increment() three times should make query_counter() return 3.
