Chapter 4: Operators

Primer: Operators

Tools for Working with Data

Operators are the verbs of a programming language, they do things to values. LPC supports the standard set: arithmetic (+ - * / %), comparison (== != < > <= >=), and logical (&& || !).

Two things catch beginners:

  • Division by zero, 10 / 0 will crash your object. Always check the divisor before dividing.
  • Integer division, 7 / 2 gives 3, not 3.5. LPC truncates; there is no rounding.

Bitwise Operators: Packing Flags

Bitwise operators (& | ^ ~ << >>) work on individual bits within an integer. MUD developers use them to pack multiple boolean flags into a single int, one bit per permission, state, or feature. If that sounds abstract now, Exercise 4.3 makes it concrete.

Read the Operators chapter of the primer before starting.

Exercise 4.1: Calculator Object Apprentice

Build a simple calculator object with functions for each arithmetic operation.

Requirements

  • Follow all standard 3K codestyle rules
  • Inherit from /obj/treasure
  • Set the name to "calculator" and short to "a calculator"
  • Implement the following functions, each taking two int arguments and returning an int:

int do_add(int a, int b)

Return a + b.

int do_sub(int a, int b)

Return a - b.

int do_mul(int a, int b)

Return a * b.

int do_div(int a, int b)

Return a / b. If b is 0, return 0 instead of crashing.

int do_mod(int a, int b)

Return a % b (the remainder). If b is 0, return 0.

File to create: exercises/ch04_operators/ex01_calculator.c

Hints (click to reveal)
  1. The five arithmetic operators are +, -, *, /, and %. They work the same as in most languages.
  2. Division by zero causes a runtime error in LPC. You must check for it before performing the division.
  3. The modulo operator % also crashes on zero. Guard it the same way as division.
  4. A simple if check is enough: if (b == 0) return 0;

Exercise 4.2: Level Classifier Apprentice

Write a function that takes a player level and returns a title string.

Requirements

  • Follow all standard 3K codestyle rules
  • Inherit from /obj/treasure
  • Set the name to "level classifier" and short to "a level classifier"
  • Implement string classify_level(int level):
Level RangeReturn Value
1 to 10"newbie"
11 to 30"adventurer"
31 to 60"veteran"
61 to 99"hero"
100 or more"legend"
0 or below"unknown"

File to create: exercises/ch04_operators/ex02_level_classifier.c

Hints (click to reveal)
  1. An if/else chain is the most readable approach: if (level >= 100) ... else if (level >= 61) ... and so on.
  2. Order matters. If you check >= 100 first, then >= 61, then >= 31, etc., each condition is clean because higher values are already handled.
  3. Do not forget the edge case: levels at or below 0 should return "unknown".
  4. For a challenge, you could write this with nested ternary operators, but readability is more important than cleverness.

Exercise 4.3: Bitwise Flags Journeyman

Implement a permission system using bitwise operators.

Background

Instead of separate status variables for each permission, pack them into one integer using bit positions:

READ    = 1   (binary: 001)
WRITE   = 2   (binary: 010)
EXECUTE = 4   (binary: 100)

A value of 5 (binary 101) means READ + EXECUTE are set, but WRITE is not.

Requirements

  • Follow all standard 3K codestyle rules
  • Inherit from /obj/treasure
  • Set the name to "flag register" and short to "a flag register"
  • Define constants: #define READ 1, #define WRITE 2, #define EXECUTE 4
  • Implement:

int set_flag(int flags, int bit)

Return flags with the given bit turned on.

int clear_flag(int flags, int bit)

Return flags with the given bit turned off.

status has_flag(int flags, int bit)

Return 1 if the given bit is set in flags, 0 otherwise.

string describe_flags(int flags)

Return a human-readable string listing which permissions are set, e.g. "READ WRITE" or "none".

File to create: exercises/ch04_operators/ex03_bitwise_flags.c

Hints (click to reveal)
  1. The bitwise OR operator | sets a bit: flags | bit turns on the bit.
  2. The bitwise AND with complement clears a bit: flags & ~bit turns off the bit.
  3. To test if a bit is set, use flags & bit. If the result is nonzero, the bit is set.
  4. For describe_flags, build a string by checking each flag in order. If no flags are set, return "none".

Capstone Connection: Phase 1 — The Foundation

Arithmetic operators calculate damage, comparison operators control game logic, and bitwise flags are used throughout 3K for monster properties, room features, and player states. These are the building blocks of every game system.
