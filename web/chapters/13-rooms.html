Chapter 13: Rooms

Read the primer: Rooms

The World is Made of Rooms

Every location a player can visit is a room object. A room defines what players see, what they can examine, where they can go, and what they can interact with. 

A Room
│
├─ set_short()       → one-line room title
├─ set_long()        → full room description
├─ add_exit()        → connects to other rooms
├─ add_item()        → examinable details
├─ add_search_item() → hidden discoveries
├─ add_read()        → readable signs/tablets
└─ add_action()      → custom commands

Rooms inherit from /room/room, which provides all the core functions for descriptions, exits, items, and player interaction.

Dungeon rooms with level scaling are covered in the optional Chapter 20.

These exercises take you from creating a single room to building rich, interactive environments with readable signs, searchable features, and custom commands.

Read the Rooms chapter of the primer before starting.

Exercise 13.1: Your First Room Apprentice

Create a basic room that a player can enter, look around in, and leave through an exit.

Requirements

  • Inherit from /room/room (the standard room base)
  • Call ::create() at the start of your create() function
  • Set room lighting with set_light(1) so players can see
  • Set a short description with set_short() (shown in brief mode and on the map)
  • Set a long description with set_long() (at least two sentences describing the room)
  • Add one exit using add_exit(path, direction), use the file's own path as the destination so it loops back to itself

File to create: exercises/ch13_rooms/ex01_first_room.c

Hints (click to reveal)
  1. Rooms use inherit "room/room";, this gives you all the standard room functionality including exits, items, and searching.
  2. set_long() takes a single string. You can break long strings across multiple lines using string concatenation: "first part " "second part" (two adjacent string literals are automatically joined).
  3. add_exit() takes two arguments: the file path of the destination room (without the .c extension) and a direction string like "north", "south", "east", "west".
  4. Remember: #pragma strong_types must be the very first non-comment line, followed by #include "defs.h", then your inherit, then your create() function.

Exercise 13.2: Room Details Apprentice

Enrich a room with examinable items, searchable features, and multiple exits.

Requirements

  • Inherit from /room/room and set up basic room properties
  • Add at least 3 add_item() calls, each with an alias array and a descriptive string: add_item(({"torch","torches","wall torch"}), "description...")
  • Add at least 2 add_search_item() calls for discoverable details when the player types search <keyword>
  • Add at least 3 exits connecting to other rooms (use placeholder paths that loop back to yourself, or connect to your ex01 room)

File to create: exercises/ch13_rooms/ex02_room_details.c

Hints (click to reveal)
  1. add_item() takes two arguments: either a string or an array of strings for the name(s), and a string description. The alias array lets you match multiple keywords.
  2. add_search_item() has the same signature as add_item(). The difference is that players must type search <keyword> instead of look at <keyword>.
  3. Think about what a player would naturally try to look at in your room. If your long description mentions torches, walls, and a door, add add_item() entries for each.
  4. Keep your descriptions immersive but concise, two or three sentences per item is ideal.

Exercise 13.3: Readable Items Journeyman

Add a readable item to a room using add_read() and a named callback function.

Requirements

  • Create a room with standard properties and at least one exit
  • Add an item that can be looked at (using add_item()) and also read (using add_read())
  • Use add_read() with a callback reference: add_read(({"sign","wooden sign"}), "@read_sign");, the @ prefix tells the driver to call the function read_sign() in this same object
  • Implement the callback function (e.g. string read_sign()) that returns a multi-line string with at least 3 lines of content
  • Include a SCREENREAD check: if TP->query_property("SCREENREAD") is true, return a plain text version (no ASCII art borders); otherwise return a decorated version

File to create: exercises/ch13_rooms/ex03_readable.c

Hints (click to reveal)
  1. add_read() works like add_item() but responds to the read command. The @function_name syntax tells it to call a function in the current object instead of returning a static string.
  2. The callback function must return a string. It takes no arguments. The driver calls it when a player reads the matching keywords.
  3. For the SCREENREAD check, use: if (TP && TP->query_property("SCREENREAD")) to branch between plain text and decorated output. This is good MUD citizenship.
  4. Multi-line strings can use \n for newlines within a single string, or you can concatenate adjacent string literals that each end with \n.

Exercise 13.4: Interactive Room Journeyman

Create a room with a custom interactive command using add_action().

Requirements

  • Create a room with standard properties and at least one exit
  • Add an init() function that calls ::init() then registers a custom command using add_action("handler_func", "verb")
  • Implement the handler function (return type int) that:
    • Returns 0 if the argument does not match
    • Checks a condition to prevent duplicates (e.g. if the player already has the object)
    • Uses clone_object() to create a new instance of an object
    • Uses move_object(obj, TP) to place it in the player's inventory
    • Uses write() and say() for player and room messages
    • Returns 1 on successful match
  • Create a simple treasure object (inherit /obj/treasure) as the cloned item

Files to create: exercises/ch13_rooms/ex04_interactive.c (the room)
exercises/ch13_rooms/ex04_hidden_item.c (the treasure object)

Hints (click to reveal)
  1. add_action("do_dig", "dig") in init() registers the verb dig so that when a player types dig <anything>, the function do_dig(string str) is called with everything after the verb as the argument.
  2. Use present("item_name", TP) to check if the player already carries an object with that name. This prevents them from farming unlimited copies.
  3. clone_object(path) creates a new copy of an object from its file path (without .c). The returned object needs to be moved somewhere with move_object().
  4. The handler must return int: return 1 if you handled the command (even for error cases), return 0 if the argument does not match your trigger word.
