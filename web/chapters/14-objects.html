Chapter 14: Objects

Read the primer: Objects

Things Players Pick Up

Objects are what players carry, examine, and use. The simplest type is a treasure, something with a name, description, weight, and gold value that can be collected and sold to shops.

All objects inherit from a base class (like /obj/treasure) that provides standard behaviors: getting, dropping, examining, and inventory management. You customize each object in create() and optionally add custom commands through init() and add_action().

These exercises teach treasures and readable objects, the foundation for the specialized item types (weapons, armor) that follow.

Read the Objects chapter of the primer before starting.

Exercise 14.1: Treasure Object Apprentice

Create a treasure object that players can pick up, examine, and sell to shops.

Requirements

  • Inherit from /obj/treasure
  • Call ::create() at the start of your create() function
  • Set the creator with set_creator("mimic")
  • Set the internal name with set_name() (lowercase, used by the game engine)
  • Set aliases with set_alias() using an array of at least 3 alternate names
  • Set a short description with set_short() (shown in inventory lists)
  • Set a long description with set_long() (at least two sentences)
  • Set a gold value with set_value() (positive integer)
  • Set a weight with set_weight() (positive integer, typically 1-5)
  • Add at least one add_item() for an examinable detail

File to create: exercises/ch14_objects/ex01_treasure.c

Hints (click to reveal)
  1. set_name() should be lowercase and is how the game engine refers to the object internally. Players use this name (and aliases) with commands like get, drop, and look at.
  2. set_alias() takes an array of strings. Include the name itself plus shorter or alternate forms: ({"ring","gold ring","signet","band"}).
  3. set_value() sets how much gold a shop will pay for the item. Typical treasures range from 10 to 500 gold.
  4. add_item() on an object works just like in rooms, it lets players examine sub-features of the object (e.g. look at engraving while holding the ring).

Exercise 14.2: Readable Object Journeyman

Create a scroll or journal object that players can read.

Requirements

  • Inherit from /obj/treasure
  • Set up standard object properties: set_creator, set_name, set_alias (3+ entries), set_short, set_long, set_weight, set_value
  • Add an init() function that calls ::init() then registers a read command: add_action("do_read", "read")
  • Implement status do_read(string str) that:
    • Returns 0 if str is missing or does not match the object (use if (!str || !id(str)) return 0;)
    • Uses write() to display multi-line text to the player (at least 5 lines)
    • Returns 1 after displaying the text
  • The long description should hint that the object can be read

File to create: exercises/ch14_objects/ex02_readable_object.c

Hints (click to reveal)
  1. init() on an object is called whenever a living being enters the same environment as the object, either the room it is in, or when picked up. This is where you register custom commands.
  2. id(str) is inherited from the base object. It returns 1 if str matches the object's name or any of its aliases. This is the standard way to check if the player is referring to your object.
  3. The status return type is used for true/false values in 3K codestyle (equivalent to int but semantically clearer).
  4. For multi-line write() output, concatenate strings: write("Line one.\n" "Line two.\n" "Line three.\n");

Capstone Connection — Phase 2: Atmosphere

Every dungeon needs loot. The treasure and readable object patterns from these exercises will appear throughout your capstone area, as quest items, collectibles, lore scrolls, and environmental flavor. Think about what kinds of objects fit your dungeon's theme.
