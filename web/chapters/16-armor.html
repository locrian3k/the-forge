Chapter 16: Armor

Read the primer: Armor

Damage Reduction Across 10 Types

Armor reduces incoming damage. On 3Kingdoms, the armor class (set_ac()) is a 10-element array matching the game's damage types: 

({ edged, blunt, fire, ice, acid, electric, mind, energy, poison, radiation })

Each piece occupies a body slot determined by its type: helmet, shield, cloak, glove, boot, armour (body), pants, belt, amulet, or ring. Note 3K uses the British spelling: /obj/armour.

Advanced armor can use wear and remove hooks, callback functions that fire when a player equips or unequips the item. These let you enforce level requirements, display thematic messages, or toggle effects.

Read the Armor chapter of the primer before starting.

Exercise 16.1: Basic Armor Apprentice

Create a piece of armor that players can wear for protection.

Requirements

  • Inherit from /obj/armour (note: British spelling with a u)
  • Call ::create() at the start of your create() function
  • Set the creator with set_creator("mimic")
  • Set the internal name with set_name() (lowercase)
  • Set aliases with set_alias() using an array of at least 3 entries
  • Set short and long descriptions (long description at least two sentences)
  • Set the armor type with set_type(), must be one of: "helmet", "shield", "cloak", "glove", "boot", "armour", "pants", "belt", "amulet", "ring"
  • Set the armor class with set_ac() using a 10-element array: ({edged, blunt, fire, ice, acid, elec, mind, energy, poison, rad}), each value typically 0-5
  • Set weight with set_weight() (typically 1-4)
  • Set gold value with set_value()

File to create: exercises/ch16_armor/ex01_basic_armor.c

Hints (click to reveal)
  1. The inherit path is /obj/armour with a u. This is a common source of errors, if you spell it "armor" the compiler will not find the file.
  2. set_type() determines which body slot the armor occupies. A player can only wear one item per slot. A hat is a "helmet", a cape is a "cloak", etc.
  3. set_ac() takes 10 integers: edged, blunt, fire, ice, acid, electric, mind, energy, poison, radiation. A steel helmet might have ({2,3,1,1,0,0,0,0,0,0}).
  4. You do not need an init() function for basic armor. The wear/remove commands are handled automatically by the base class.

Exercise 16.2: Wear/Remove Hooks Journeyman

Create a piece of armor with custom wear and remove hooks.

Requirements

  • Inherit from /obj/armour
  • Set up standard armor properties: set_creator, set_name, set_alias, set_short, set_long, set_type, set_ac, set_weight, set_value
  • Register wear/remove hooks in create():
    • set_wear_func(TO), calls do_wear() when worn
    • set_remove_func(TO), calls do_remove() when removed
  • Implement status do_wear():
    • Check a condition (e.g. player level >= 10 using (int)TP->query_level())
    • If the condition fails: call notify_fail() with an explanatory message and return 0
    • If the condition passes: use write() to show a thematic wear message and return 1
  • Implement status do_remove():
    • Use write() to show a thematic remove message
    • Return 1 (always allow removal)

File to create: exercises/ch16_armor/ex02_wear_hooks.c

Hints (click to reveal)
  1. set_wear_func(TO) registers this object as the handler for wear events. The driver will call do_wear() (no arguments) whenever a player tries to wear this armor. Return 1 to allow, 0 to deny.
  2. notify_fail() sets a failure message shown to the player when you return 0. Always call it before returning 0 so the player knows why.
  3. (int)TP->query_level() returns the current player's level. The cast (int) is required by #pragma strong_types.
  4. set_remove_func(TO) works the same way but calls do_remove(). You almost always return 1 from remove hooks.

Capstone Connection — Phase 3: Combat

Armor drops give players a reason to explore your dungeon thoroughly. Use basic armor for common monster drops and the wear hook system for special pieces that require earning. A level-gated armor piece from a mini-boss makes for a satisfying mid-dungeon reward.
