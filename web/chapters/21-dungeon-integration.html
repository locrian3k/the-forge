Chapter 21: Dungeon Integration

Read the primer: Integration

3K Extension. This chapter covers the dungeon room system specific to 3Kingdoms. Skip it if your MUD does not have /room/dungeon/dr.c.

Building a Complete Dungeon Area

Chapter 18 showed how to organize an area with standard rooms. This chapter applies the same architecture to dungeon rooms, adding level scaling and the convenience of add_clone() for spawning.

The typical dungeon area pattern uses three layers:

FileInheritsPurpose
entrance.c/room/roomOutdoor entry point, no scaling
droom.c/room/dungeon/dr.cBase dungeon room with shared setup
rm2.c, rm3.c, ...droom.cIndividual dungeon rooms

The droom.c base room calls set_dungeon() once so child rooms do not repeat it. It can also define helper functions like monster(path) and item(path) that wrap add_clone() with the area's path constants, keeping child rooms short and consistent.

The entrance room inherits /room/room because it sits outside the dungeon. Players pass through it to enter the scaled area. Inside the dungeon, every room inherits droom.c and benefits from automatic scaling and the add_clone() respawn system.

Exercise 21.1: Base Dungeon Room Journeyman

Create an inheritable base dungeon room with set_dungeon(), monster/item clone helpers, and a direction blocker.

Requirements

  • Include the header with #include "../defs.h" (ex01_droom.c lives in rooms/ subdirectory)
  • Inherit from /room/dungeon/dr.c
  • Define a create() that calls ::create(), calls set_dungeon(DNAME, level, 1, 1, 1) with a level of your choice, and sets light
  • Define a monster(string path) helper that calls add_clone(TRAINING_MOBS + path)
  • Define an item(string path) helper that calls add_clone(TRAINING_ITEM + path)
  • Define a block_them(string arg) function that:
    • Uses query_verb() to get the direction the player typed
    • Checks if the direction exists in query_exits() or query_hidden()
    • Blocks movement (returns 1) if the direction is not a valid exit
    • Allows movement (returns 0) if the direction is a valid exit
  • Define an init() that calls ::init() and registers block_them with add_action("block_them", "", 1)

File to create: exercises/ch21_dungeon_integration/ex01_droom.c

Hints (click to reveal)
  1. The ex01_droom.c file acts as a middle layer: it inherits /room/dungeon/dr.c and your actual rooms inherit ex01_droom.c. This lets you put common setup in one place.
  2. add_clone(path) is a dungeon room function that clones an object and moves it into the room. It handles reset/respawning automatically, so the monster() and item() helpers are thin wrappers for convenience.
  3. block_them() prevents players from walking into walls. The add_action("block_them", "", 1) trick catches ALL player commands, so you check whether the verb matches a valid exit direction.
  4. query_exits() returns a mapping of visible exits. query_hidden() returns hidden exits. Use member(mapping, key) to check if a direction exists in either.

Exercise 21.2: Mini Dungeon Layout Journeyman

Create an entrance room and three connected dungeon rooms that inherit your base room.

Requirements

Create four files:

  • ex02_entrance.c, The outdoor entrance:
    • Inherit from /room/room (not a dungeon room)
    • Set light, short, and long descriptions
    • Add at least 2 add_item() calls
    • Add an exit leading into the dungeon (to TRAINING_ROOM + "ex02_rm2")
  • ex02_rm2.c, First dungeon room:
    • Inherit from ex01_droom.c (your base dungeon room from Exercise 21.1)
    • Set short and long descriptions
    • Exits: back to entrance, forward to rm3
    • Use monster() helper to spawn a monster
  • ex02_rm3.c, Second dungeon room:
    • Inherit from ex01_droom.c
    • Exits: back to rm2, forward to rm4
    • Use item() helper to place a treasure
  • ex02_rm4.c, Third dungeon room (dead end):
    • Inherit from ex01_droom.c
    • Exit: back to rm3
    • Use monster() helper to spawn a tougher monster

All rooms must have bidirectional exits, use TRAINING_ROOM defines for paths, and follow 3K codestyle.

Files to create: exercises/ch21_dungeon_integration/ex02_entrance.c
exercises/ch21_dungeon_integration/ex02_rm2.c
exercises/ch21_dungeon_integration/ex02_rm3.c
exercises/ch21_dungeon_integration/ex02_rm4.c

Hints (click to reveal)
  1. The entrance room inherits /room/room because it is outdoors and does not need dungeon scaling. All interior rooms inherit ex01_droom.c, which already calls set_dungeon().
  2. Because ex01_droom.c handles set_dungeon(), light, and the direction blocker, your child rooms only need to set descriptions, add items/exits, and call the monster() or item() helpers.
  3. The monster() helper takes just the filename, not the full path. For example: monster("goblin") expands to add_clone(TRAINING_MOBS + "goblin").
  4. Remember to create the monster and treasure files that your rooms reference. Simple /obj/monster and /obj/treasure inherits work fine for testing.

Exercise 21.3: Reset Respawning Journeyman

Create a dungeon room that uses reset() and add_clone() to respawn monsters.

Requirements

  • Inherit from the ex01_droom.c base room created in Exercise 21.1
  • Define a create() that:
    • Calls ::create()
    • Sets short and long descriptions
    • Adds at least 1 add_item() for scenery
    • Adds at least 1 exit
    • Uses the monster() helper to spawn an initial monster
  • Define a reset() that:
    • Calls ::reset() (important for dungeon internals)
    • Uses add_clone() to spawn 1-2 monsters
    • add_clone() handles duplicate checking internally, so it will not create extras if the monster still exists

File to create: exercises/ch21_dungeon_integration/ex03_spawn_room.c

Hints (click to reveal)
  1. reset() is called by the driver periodically (roughly every 30-45 minutes) to repopulate rooms. It is also called once after create() when the room first loads.
  2. Always call ::reset() at the start of your reset() function. The parent's reset handles internal dungeon bookkeeping.
  3. add_clone(path, count, chance, unique) is the full signature. add_clone(TRAINING_MOBS + "goblin") spawns one goblin. The system will not spawn duplicates if one already exists.
  4. The monster() helper from ex01_droom.c is a shorthand that calls add_clone(TRAINING_MOBS + path). You can use either in reset().
